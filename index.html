The cost of a secret

Complexity asks how work grows when the input grows. A timing side channel appears when that work also depends on a secret. This page counts operations in a small model of both ideas. It does not time a real machine.

    02 · Timing side channels

    When the cost depends on a secret

    Both routines compare a guess with a secret at a fixed width. Stop-early can return on the first difference, so its step count is tied to the shared prefix. Check-every always walks the whole width, so its step count is the width. You can see the secret. The point is to watch the cost, not to hide a target.

    Width equals the secret’s length, up to 12 characters. A short guess is padded with missing characters. Extra guess characters are not read. The text stays in this browser tab.

    Enter in the guess field plays the walk.

    Secret Guess

    Secret-independent, and still O(n). Check-every is linear in the public width: a longer secret does more work. Changing a character inside that width does not change the count. O(1) would be a further claim, that the count stays put when the width grows.

    The second loop fixes the iteration count in this model. On a real machine, a branch or a memory lookup that depends on a secret can still leak. This lab stops at the iteration count and leaves that next problem named.
